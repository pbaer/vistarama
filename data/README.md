# `data/` layout

Four tiers, each reproducible from the one above it. Only `raw/` is
irreplaceable, and only because re-downloading is slow — nothing in it is
edited, ever.

Nothing here except `aoi/` and this file is in git (see `.gitignore`). The
Alpine Lakes AOI is ~11 GB, most of it the NAIP mosaic.

```
data/
  aoi/                     AOI definitions (bboxes, CRS choices)  — hand-authored, tracked
  raw/                     as downloaded, never modified
    3dep-1as/              USGS 3DEP 1 arc-second DEM tiles (EPSG:4326)
    worldcover-v200/       ESA WorldCover 10 m 2021 tiles (EPSG:4326)
    rgi7/                  Randolph Glacier Inventory 7.0, region 02 (needs a
                           login; empty here, OSM glaciers are used instead)
    osm/                   Overpass extracts, one GeoJSON per theme
    prominence/            Kirmse & de Ferranti p100 zip, fetched by hand
                           (see the main README's Quick start)
    <aoi>/                 Sentinel-2 mosaic in its native UTM zone, plus the
                           STAC scene/quad lists for both imagery sources
  interim/<aoi>/           mosaics + reprojections: DEM, land cover, the two
                           imagery mosaics, peak_prominence.json
  derived/<aoi>/           computed metric layers
  web/<aoi>/               viewer-ready tiles (PNG, JPEG for imagery),
                           zoom-tiered GeoJSON, manifest.json
  imagery.log              log from the last scripts/imagery.py run
```

The NAIP mosaic is the one exception to "raw first": `scripts/imagery.py`
reads each quad from Planetary Computer through its COG overviews and writes
straight into `interim/<aoi>/imagery_naip_5070.tif` at 2 m. Keeping the
0.6 m quads would have meant tens of GB in `raw/` for no use.

## Rules

- **`raw/` is immutable.** Delete it and re-run `scripts/download.py` to
  restore. Never write processed output here.
- **`interim/` and `derived/` are disposable.** Regenerated by
  `scripts/process.py`, except the NAIP mosaic and `peak_prominence.json`,
  which come from `scripts/imagery.py` and `scripts/prominence.py`. Safe to
  delete to reclaim space, at the cost of re-running those.
- **`web/` is disposable.** Regenerated from `derived/`.
- Everything below `raw/` is keyed by **AOI slug**, so multiple regions coexist
  without collision.
- Raw filenames are kept **exactly as the publisher named them**, so provenance
  is legible without a manifest.

## CRS policy

Three different projections, each for a specific reason. This matters — see
[../docs/aoi-manifest.md](../docs/aoi-manifest.md).

| Tier | CRS | Why |
|---|---|---|
| `raw/` | EPSG:4326 | as published |
| `interim/`, `derived/` | **EPSG:5070** (CONUS Albers) | **equal-area** — required for the ruggedness kernel and slope/hillshade to be honest in metres |
| `web/` | EPSG:3857 | Web Mercator, what Leaflet expects |

Computing ruggedness in EPSG:4326 would make the kernel radius vary with
latitude and fabricate a north–south gradient. All metric computation happens
in 5070; reprojection to 3857 is display-only and happens last.

For European AOIs the metric CRS becomes EPSG:3035 (ETRS89-LAEA).

## Resolutions

| Layer | Resolution | Rationale |
|---|---|---|
| DEM | 30 m | 1 arc-second, uniform across all AOIs for cross-region comparability |
| Hillshade, slope | 30 m | the DEM's own grid |
| Land cover | 10 m | native WorldCover |
| Canopy / built-up density | **10 m**, 100 m radius | the gate has to resolve clearings, treeline and forest edges; a wide kernel smooths away the boundaries it exists to detect. Stored uint8 percent — float32 at 10 m would be 2.2 GB for data with ~1% useful precision |
| Ruggedness | 120 m grid | slope-vector variety: 240 m gradient baseline, 600 m window, averaged over a 5 km biweight kernel (`ruggedness_near`: 1.5 km). At these kernel sizes finer sampling is indistinguishable and ~16× more expensive |
| Relief | 120 m grid | elevation σ over a 10 km biweight kernel, permanent water excluded |
| Openness (+, −, defect) | 60 m grid | Yokoyama openness, 8 azimuths out to 1.2 km |
| Sentinel-2 imagery | 10 m | native |
| NAIP imagery | 2 m | native is 0.6 m; see the main README's "What's not done" |

Higher-resolution DEMs exist for Washington (WA DNR lidar) and are deliberately
not used for scoring — see the manifest doc for why.

## What is precomputed vs. computed on the fly

The map is entirely precomputed: nothing in `web/` is generated per request.
The panorama is the opposite. Its mesh, imagery textures and summit snapping
are computed by `serve.py` for each viewpoint from `interim/` and `derived/`,
which is why those GeoTIFFs have to stay on disk even though the map never
reads them.

| Artefact | Built by | Reused when |
|---|---|---|
| Raster XYZ pyramid | `process.py` | `layers/<id>/_complete.json` exists |
| Vector LOD tiers + grid cells | `process.py` | rebuilt whenever `process.py` runs |
| interim / derived GeoTIFFs | `process.py` | file exists |
| Imagery mosaics | `imagery.py` | file exists (`--fill-gaps` resumes a partial NAIP run) |
| `peak_prominence.json` | `prominence.py` | rebuilt whenever it runs |
| Panorama mesh + textures | `serve.py`, per request | never; only whole rasters are cached in memory |

The completion marker matters: "does this directory contain any PNG?" answers
yes for a pyramid whose generation was interrupted half way, and that partial
result would then be reused forever.

On the wire, `serve.py` sends `max-age=86400` for anything under `layers/` or
`vectors/`, and `no-store` for the viewer source and manifest. Without the
former the browser refetches every tile on every pan, which throws away the
entire benefit of precomputing a pyramid.
